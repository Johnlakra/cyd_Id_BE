### Shipped (backend, additive only)

- `middleware/anubhavRole.js`
  - Added `requireAdminOrDexco` guard (admin role bypass + dexco event_role; everything
    else returns 403). Exported it. Existing exports/behavior unchanged.

- `controllers/anubhavAccommodationController.js`
  - Imported `pool` from `config/database.js`.
  - Added `runInTransaction(steps)` helper that opens a connection, begins a
    transaction, runs all `[sql, params]` pairs, commits, and rolls back on error.
  - Added `deleteBuilding`, `deleteFloor`, `deleteRoom`. Each:
    - parses id, 400 on bad id, 404 if parent row not found
    - resolves place via parent and applies `locScopeBlocked` defence-in-depth
    - runs the cascade inside the transaction:
      * building -> allotments under its rooms -> rooms -> floors -> building
      * floor    -> allotments under its rooms -> rooms -> floor
      * room     -> allotments of the room -> room
    - returns `{ success, message, data: { id } }`
  - Registrations and profiles are NEVER touched (spec requirement).
  - `getRoomingData` SELECT now pulls `p.photo_url AS occupant_photo_url` and the
    pushed occupant object includes `photo_url: row.occupant_photo_url || null`.
    No other field changed. PDF output untouched (per spec).

- `routes/anubhav.js`
  - Imported `requireAdminOrDexco`.
  - Mounted (after `/rooming`, before Phase 3):
    ```
    DELETE /anubhav/buildings/:id  (requireAdminOrDexco)
    DELETE /anubhav/floors/:id     (requireAdminOrDexco)
    DELETE /anubhav/rooms/:id      (requireAdminOrDexco)
    ```
  - URL carries no `place`, so no `requirePlaceAccess` in the chain; LOC scoping
    is enforced in-controller against the parent building's place.
