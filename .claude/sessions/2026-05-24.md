## Role Management — User Search + Direct Grant (api-builder work, this session)

### Problem identified
`POST /anubhav/roles/grant` required a `profile_id` and resolved the target user via
`profile.profile_user_id`. Users without a linked profile (or admins wanting to search
by name/phone) had no path to assign LOC/DEXCO roles — no UI and a restrictive API.

### What shipped

#### `controllers/anubhavRoleController.js` — two additions

**`searchUsers`** (new function):
- Searches `profile` by name, phone, or father_name (LIKE).
- JOINs `users` on `profile.profile_user_id` (LEFT JOIN — profiles without a login are included and flagged).
- Returns up to 30 results: `{ profile_id, profile_name, phone, deanery, parish, photo_url, user_id, username, email, system_role, event_role, loc_place }`.
- `user_id = null` means the profile has no login account (cannot be promoted until one is created).

**`grantRole`** extended:
- Now accepts `user_id` directly **in addition to** `profile_id`.
- If `user_id` is provided, resolves directly to the user row (no profile lookup needed).
- If `profile_id` is provided (old path), resolves via `profile.profile_user_id` as before.
- Validation: requires `profile_id` OR `user_id`, plus valid `event_role`.

#### `routes/anubhav.js` — one new route
```
GET /anubhav/users/search?q=   (admin only)
```
Returns search results for the role management UI.

### Endpoints now live
| Method | Path | Access | Description |
|--------|------|--------|-------------|
| GET | `/anubhav/users/search?q=` | admin | Search profiles by name/phone for promotion |
| POST | `/anubhav/roles/grant` | admin / dexco | Grant role by `profile_id` OR `user_id` |
